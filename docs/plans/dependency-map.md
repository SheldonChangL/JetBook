## 3. Critical Path 與並行建議

### Critical Path（最長串行鏈，delay 直接影響上線日）

```
A-01 → A-02 → A-04 → B-01 → C-01 → C-02 → B-03 → D-02 → E-01 → F-01
     → [N-02 MVP 閘門/上線] → H-06(前置 H-01/H-04/H-05 可並行完成)
     → I-01 → I-02 → I-03 → I-04 → [N-04 M2 閘門]
```

Critical path 上的 task 已標 `critical-path` label。兩個閘門：**N-02**（MVP E2E 全綠才上線，含雙人編輯鎖情境）、**N-04**（RAG 權限隔離測試通過才開放 AI 功能，`release-blocker`）。

新增的 B-08/C-13/M-03 均不在 critical path 上，不影響閘門時程。

### 排程要點

1. **A-10（中文斷詞 spike）放 M0**：它是 F-01 的前置，也是全案少數技術不確定點，最早去風險（R2：50–100 份真實文件＋20 條驗收查詢）。
2. **B-03 存在刻意的先後安排**：先由 B-01/C-01/C-02 定 schema（含「schema 一次補齊」——groups/group_members、visibility 三態、commenter 角色、page_slug_history、page_visits、space_pinned_pages、collections 預留、pages 鎖欄位，C3/C4/C5/G1/G8/G9/G10），B-03 統一實作授權，之後所有入口回接——避免權限判斷散落，也避免 M3 群組功能（K-03）回頭改表。
3. **M1 尾聲讓 1 人先跑 H-02/H-04/H-05**（純介面與純函式，不依賴 M1 UI），可將 M2 期程壓縮約三分之一。
4. **N-01（真 PG 測試基建）盡早落地**：它是 N-04 出貨閘門的基礎，也是權限模型重構的安全網。
5. **M3 起手先做 M-03 與 C-08**：M-03 依賴（M-01/H-01）於 M2 結束即全數就緒；C-08（回收桶）是 C-13 的前置，早做可讓 C-13 只等 D-11。
6. **C-13 排 M3 尾段**：同時依賴協作線的 D-11 與結構線的 C-08，是 M3 的自然收尾項；驗收時順帶回歸 F-EDIT-12 連結更新行為。
