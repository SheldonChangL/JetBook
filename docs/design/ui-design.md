## 1. 資訊架構與導航模型

### 1.1 內容層級模型

```
Organization（單一，即公司）
└── Space（知識空間，例：研發手冊、行政流程、產品文件）
    └── Page（頁面，可無限層級巢狀成頁面樹）
        └── Block（段落、標題、程式碼、圖片、表格、callout…）
```

- Page 支援巢狀（建議 UI 上顯示至第 5 層，超過仍可展開但縮排封頂）。
- 另有貫穿全域的物件：使用者、群組、評論、版本、AI 對話。

### 1.2 全域導航（App Shell）

**頂部列（Global Top Bar，高 56px，固定於頂端）**，由左至右：

| 區塊 | 內容 |
|---|---|
| 左 | JetBook Logo（點擊回 Dashboard）＋ Space 切換器（下拉，顯示目前 space 名稱與 icon） |
| 中 | 搜尋觸發器：仿輸入框的按鈕，placeholder「搜尋或問 AI…」，右側顯示 `⌘K` kbd 標籤。點擊開啟 Cmd+K modal |
| 右 | 「新增」按鈕（＋，下拉：新頁面／新 Space）→ AI 助手按鈕（開啟 AI 抽屜）→ 通知鈴鐺（含未讀紅點，點擊開啟通知中心面板 §3.17）→ 使用者頭像選單（個人設定、深色模式切換、管理後台入口、登出） |

**導航層級劃分原則**：頂部列＝跨 space 全域功能；左側欄＝space 內導航；右側欄＝頁內導航。三層各司其職，不互相混雜。

### 1.3 Space 內導航（左側欄）

- 頂部：Space 名稱＋icon＋權限徽章（私人／團隊／全公司）。
- 側欄內搜尋（篩選頁面樹，即時 filter）。
- 頁面樹（Tree 元件，詳見 §2 與 §4.5）。
- 底部固定區：「垃圾桶」（僅該 Space 的回收桶，F-PAGE-06；全域彙整入口見 §3.2，C12）、「Space 設定」（有權限者才顯示）。

### 1.4 麵包屑

- 位置：內容區頂部，內容標題上方。
- 結構：`Space 名稱 / 上層頁面 / … / 目前頁面`。
- 超過 4 層時中間折疊為 `…`（點擊展開下拉顯示完整路徑）。
- 每一節皆可點擊；最末節（目前頁面）為純文字不可點。
- 行動裝置：只顯示「上一層 ‹ 返回」單一節點。

### 1.5 鍵盤快捷鍵

| 快捷鍵 | 功能 | 範疇 |
|---|---|---|
| `⌘K` / `Ctrl+K` | 開啟全域搜尋；**雙義（C11）**：編輯模式且有文字選取時＝插入超連結（F-EDIT-03），其餘情境＝全域搜尋 | 全域 |
| `⌘J` | 開啟／關閉 AI 助手抽屜 | 全域 |
| `⌘\` | 收合／展開左側欄 | 全域 |
| `⌘⇧D` | 切換深色模式 | 全域 |
| `?` | 快捷鍵說明 modal | 閱讀模式 |
| `E` | 進入編輯模式（有權限且無他人持鎖時） | 閱讀模式 |
| `C` | 開啟評論側欄 | 閱讀模式 |
| `[` / `]` | 上一頁／下一頁（頁面樹順序） | 閱讀模式 |
| `⌘S` | 儲存（實際為自動儲存，按下顯示「已儲存」回饋，C2） | 編輯模式 |
| `⌘Enter` | 完成編輯（釋放編輯鎖，返回閱讀模式，C2） | 編輯模式 |
| `/` | 開啟 slash 選單 | 編輯模式（行首或空白處） |
| `@` | 頁面／使用者 mention | 編輯模式 |
| `⌘B` `⌘I` `⌘U` `⌘⇧X` `⌘E` | 粗體／斜體／底線／刪除線／行內程式碼 | 編輯模式 |
| `⌘⌥1~3` | 標題 H1–H3（C11：標題層級統一 H1–H3，頁面標題即 H1） | 編輯模式 |
| `Esc` | 關閉 modal／抽屜／選單（層層退出） | 全域 |
| `↑↓ Enter` | 選單與搜尋結果導航 | 所有 listbox |

- 所有快捷鍵在 Tooltip 與選單項目右側以 `Kbd` 元件顯示。
- Windows 環境自動將 `⌘` 顯示為 `Ctrl`。
- 輸入中文（IME composition 中）時，單鍵快捷鍵（E、C、?、[、]）必須停用，避免與注音／倉頡輸入衝突（監聽 `compositionstart/end`）。

## 2. 核心版面：閱讀模式三欄式

### 2.1 欄位規格（桌面 ≥1440px 基準）

```
┌──────────────────────────────────────────────────────────────┐
│ Global Top Bar（56px 高，全寬，z-index 最高層）                  │
├───────────┬───────────────────────────────────┬──────────────┤
│ 左側欄     │ 內容區                              │ 右側 TOC      │
│ 280px     │ flex-1（內文欄 max-width 720px 置中） │ 240px        │
│ 可拖曳     │ 左右 padding ≥48px                  │              │
│ 240–400px │                                    │              │
└───────────┴───────────────────────────────────┴──────────────┘
```

| 項目 | 規格 |
|---|---|
| 左側欄 | 預設 280px；右緣可拖曳調整 240–400px（寬度記憶於 localStorage）；獨立捲動；背景色比內容區低一階（`--bg-sidebar`），右緣 1px 邊框 |
| 內容區 | 內文欄 `max-width: 720px`（中文約 42–45 字/行，最佳閱讀寬度）置中；寬型內容（大表格、圖片）可單塊「跳出」至 max-width 960px |
| 右側 TOC | 固定 240px；`position: sticky; top: 88px`；只取內文 H2/H3 生成（頁面標題即 H1，C11；F-EDIT-19）；捲動時以左緣 2px 指示條＋文字變色標示目前章節（scroll-spy）；獨立捲動 |

### 2.2 收合行為

- **左側欄**：`⌘\` 或側欄頂部收合鈕 → 完全收起（非 icon rail）。收起後頂部列左側出現「☰ 展開」按鈕；滑鼠移至視窗左緣 8px 熱區時側欄以 overlay 浮出（不推擠內容），移開即收回。收合狀態記憶。
- **右側 TOC**：無手動收合；隨斷點自動隱藏。當頁面 H2/H3 少於 2 個時整欄不渲染，空間還給內容區。

### 2.3 響應式斷點

採 Tailwind 標準斷點：`sm 640 / md 768 / lg 1024 / xl 1280 / 2xl 1536`。

| 視窗寬度 | 版面行為 |
|---|---|
| ≥1280px（xl） | 完整三欄 |
| 1024–1279px（lg） | 隱藏右側 TOC；改為內容頂部麵包屑列右端的「本頁目錄」下拉按鈕 |
| 768–1023px（md） | 左側欄改為 overlay 抽屜（預設收起，☰ 開啟，半透明遮罩，`Esc`/點遮罩關閉）；單欄內容 |
| <768px（sm 以下） | 單欄；頂部列簡化為「☰ ＋ 頁面標題 ＋ 搜尋 icon ＋ 頭像」；內容 padding 16px；AI 抽屜與搜尋 modal 改為全螢幕 |

- AI 抽屜（見 §3.7）開啟時：≥1536px 與內容並存（推擠版面）；<1536px 以 overlay 疊加。

### 4.3 間距、圓角、陰影、邊框

- **間距**：4px 基準格。scale：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`。元件內距用 8–16，區塊間距用 24–48。
- **圓角**：`4px` 小元件（badge、kbd、行內 code）；`6px` 按鈕/輸入框；`8px` 卡片/popover；`12px` modal/抽屜；`9999px` 頭像、pill。
- **陰影**（dark mode 陰影透明度加倍並輔以邊框）：
  - `sm`：`0 1px 2px rgb(16 24 32 / .06)` — 卡片 hover
  - `md`：`0 4px 12px rgb(16 24 32 / .10)` — dropdown、popover
  - `lg`：`0 8px 24px rgb(16 24 32 / .14)` — modal、抽屜
- **邊框**：一律 1px；輸入框 focus 時轉為 `primary-600`＋外圈 focus ring（見 §5.2）。

### 5.1 深色模式策略

- 三段設定：淺色／深色／跟隨系統（預設跟隨系統）。位置：頭像選單＋個人設定（§3.15）。
- 實作：`html` 上掛 `.dark` class；首屏於 `<head>` inline script 讀 localStorage/系統偏好後立即設 class（防 FOUC）；登入使用者同步存於 profile（跨裝置一致）。
- 深色模式規則：不用純黑（`#0F141A` 底）、文字不用純白；陰影減效改以「底色升階＋1px 邊框」表達層次；使用者上傳圖片不反色，但白底圖在 dark 下加 `bg-white` 襯底＋圓角避免刺眼；程式碼區塊雙主題各配一套語法高亮（light 用淺底深字、dark 用 `#141B22` 底）。
- 所有色彩對比需在**兩種模式各自驗證**通過 AA。

### 5.2 無障礙（WCAG 2.1 AA）

- **對比**：一般文字 ≥4.5:1；≥18.66px 粗體或 ≥24px 文字 ≥3:1；UI 元件邊界與圖示 ≥3:1。上表 token 已按此校準（`text-tertiary` 於淡底上僅用於非必要資訊）。
- **Focus ring**：全站統一 `outline: 2px solid var(--primary-600); outline-offset: 2px`（dark 用 `primary-400`）；僅 `:focus-visible` 顯示（滑鼠點擊不顯示）；永不 `outline: none` 而無替代。
- **鍵盤**：所有互動皆可鍵盤完成；modal/drawer focus trap 並於關閉後歸還 focus 至觸發元素；跳過連結（skip link）「跳至主要內容」為 tab 第一站；Tree/Menu/Tabs 遵循 WAI-ARIA APG 方向鍵模式。
- **語意**：地標 `header/nav/main/aside`；圖片必填 alt（編輯器上傳時提示輸入，可留空標記 decorative）；toast 用 `aria-live=polite`、錯誤用 `assertive`；AI 串流區塊 `aria-busy` 標記。
- **動態**：`prefers-reduced-motion: reduce` 時停用所有過場與 shimmer（改靜態淡色）。
- 觸控目標 ≥40×40px（行動斷點下按鈕自動升級尺寸）。

### 5.3 載入與骨架屏策略

- **骨架屏原則**：結構可預期的區塊用 skeleton（頁面樹：8 條漸短灰條；文件內容：標題粗條＋段落細條組；Dashboard：卡片框架；搜尋語意區：3 列）；結構不可預期的用 spinner。
- **300ms 規則**：載入 <300ms 不顯示任何指示（避免閃爍）；skeleton 至少停留 300ms 再切換（避免跳動）。
- **路由過場**：頂部 2px primary 進度條（indeterminate）；側欄與頂部列為 layout 常駐不重載，只有內容區換骨架。
- **樂觀更新**：評論送出、表情回應、頁面樹拖曳排序、標記解決——先更新 UI，失敗時回滾＋error toast。
- **串流**：AI 回覆逐 token 渲染；長文件採 SSR＋streaming（Next.js App Router `loading.tsx` 配合 Suspense）。
- **圖片**：`next/image` 懶載入＋固定長寬比佔位（防 CLS）；lightbox 預載相鄰圖。

## 6. 繁體中文排版注意事項

1. **行高**：中文方塊字視覺密度高，內文行高 1.75（16px/28px），低於 1.6 會明顯擁擠；標題可降至 1.4–1.55。段落間距 16px、不做首行縮排（web 慣例）。
2. **中英混排間距**：中文與英數字之間需 1/8–1/4 em 視覺間隙。策略：CSS `text-autospace`（2025 起 Chromium/Safari 已支援）為主，`@supports not` 時接受原樣降級、不做 JS 注入空格（會污染複製內容與搜尋索引）；編輯器儲存的原文一律不插空格。
3. **字重**：Noto Sans TC 避免使用 300 以下（螢幕上過細、對比不足）；正文 400、強調與 UI 標籤 500、標題 600–700。中文粗體對比較弱，重要強調可疊加語意色而非只加粗。
4. **斜體禁用**：中文無原生斜體（瀏覽器偽斜只是機械傾斜、可讀性差）。編輯器 `⌘I` 對中文段落的呈現改為「強調底色」（primary-50 highlight）；引用（blockquote）以左緣色條＋`text-secondary` 呈現而非斜體。
5. **斷行**：`overflow-wrap: break-word; line-break: strict`（禁止行首出現 、。」？ 等標點）；標題用 `text-wrap: balance` 避免孤字成行；長 URL/code 允許 `anywhere`。
6. **標點**：全形標點統一（介面文案用「」引號、全形逗句號）；`hanging-punctuation` 尚不可依賴，接受標點不懸掛。
7. **數字與日期**：介面數字用半形；相對時間格式「3 分鐘前／昨天 14:30／2026/07/06」；數字與中文單位間留半形空格（「5 分鐘」「120 頁」）。
8. **行長**：內文欄 720px 於 16px 字級約 42 字/行，落在中文最佳 35–45 字區間；勿讓內文滿版延展。
9. **搜尋高亮**：`<mark>` 高亮需支援 CJK 分詞命中（後端 PG 全文檢索的中文分詞採 **zhparser 或 pgroonga，由 M0 spike 定案**（R2/C12，審查傾向 pgroonga）；前端高亮以命中詞而非單字為單位）。
10. **IME 相容**：所有 Enter 送出的輸入框、單鍵快捷鍵、slash/@ 選單，都必須處理 `isComposing`（選字中的 Enter/方向鍵不得觸發 UI 行為）——這是繁中產品最常見的體驗破口，列為驗收必測項。
